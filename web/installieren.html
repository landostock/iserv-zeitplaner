Konten anmelden

Hier installieren Sie Ihre eigene Website. Danach richten Sie dort die Anmeldung und IServ ein.

Melden Sie sich zuerst bei GitHub, dann bei Cloudflare an. Falls Sie noch kein Konto haben, legen Sie eines im kostenlosen Tarif an.

1. GitHub ↗Anmelden oder Konto anlegen2. Cloudflare ↗Anmelden oder Konto anlegen

Öffnen Sie Cloudflare und schauen Sie unter Git account:

Ist Ihr GitHub-Name schon aufgeführt, wählen Sie ihn aus. Andernfalls klicken Sie auf „New GitHub connection“.

Cloudflare öffnen ↗

Prüfen Sie im GitHub-Fenster Ihr Konto. Erscheint zuerst Authorize, bestätigen Sie diesen Dialog. Wählen Sie anschließend:

  1. All repositories
  2. Install & Authorize

Cloudflare erhält damit Zugriff auf alle GitHub-Projekte. Diesen Zugriff grenzen Sie nach der Installation ein.

Aktivieren Sie bei Cloudflare Create private Git repository und tragen Sie diese beiden Angaben ein:

SETUP_CODE

Im Passwortmanager einen zufälligen Code mit mindestens 24 Zeichen erzeugen und speichern. Nur bei Cloudflare eintragen.

Installation öffnen ↗

Warten Sie in Cloudflare, bis die Bereitstellung erfolgreich abgeschlossen ist.

Success

Öffnen Sie bei GitHub Cloudflare Workers and Pages → Configure.

  1. Only select repositories wählen.
  2. Ihre Zeitplaner-Kopie auswählen und mit Save speichern.

Andere bereits mit Cloudflare verbundene Projekte ausgewählt lassen.

GitHub-Einstellungen öffnen ↗

Die Installation ist abgeschlossen. Fügen Sie die workers.dev-Adresse aus Ihrem Cloudflare-Projekt ein.

Auf Ihrer Website geht es mit Teil 2 weiter: fünf Schritte für Anmeldung, IServ und einen Veröffentlichungstest. GitHub und Cloudflare müssen Sie dort nicht erneut einrichten.

Einrichtungscode und IServ-Passwort erst auf Ihrer eigenen Website eingeben.

Hilfe

Registrierung und Bestätigung

Wählen Sie jeweils den kostenlosen Tarif und bestätigen Sie Ihre E-Mail-Adresse. Bei neuen GitHub-Konten kann eine Geräteprüfung oder CAPTCHA erscheinen. Schließen Sie diese direkt beim Anbieter ab. Wird das Konto eingeschränkt, hilft erneutes Anmelden allein nicht; folgen Sie dem Hinweis des Anbieters.

Cloudflare-Anmeldung

Haben Sie bereits ein Cloudflare-Konto, verwenden Sie dessen bisherigen Anmeldeweg. Cloudflare bietet auch „Continue with GitHub“ an, kann für API-Token aber später ein eigenes Passwort verlangen. Die Anmeldung bei Cloudflare und die spätere Freigabe des Programmcode-Repositorys sind getrennte Schritte.

Kosten und Zugriffsrechte

Wird ein kostenloses Nutzungslimit erreicht, kann der Dienst ausfallen. Geben Sie dem Entwickler keine Verwaltungsrechte für Ihre Konten. Prüfen Sie den Programmcode und Updates selbst oder mit einer Person Ihres Vertrauens.

GitHub fragt nach dem Konto

Wählen Sie „Continue as“ mit Ihrem eigenen GitHub-Namen. Andere angezeigte Konten nicht verwenden.

Ich sehe „Select a repository“

Öffnen Sie die Vorlage erneut. Wählen Sie dort keines Ihrer anderen Projekte aus.

Zeitplaner-Vorlage erneut öffnen ↗

„Only select repositories“

Wenn Sie Cloudflare schon für bestimmte bestehende Projekte freigeben möchten, können Sie nur diese auswählen. Laut GitHub erhält die App automatisch auch Zugriff auf von ihr neu erstellte Repositories. Bei einem neuen Konto ohne Repositories verwenden Sie für diesen Ablauf „All repositories“.

Weitere Einstellungen

Build command: npm run build
Deploy command: npm run deploy
„Enable Preview builds“ ausschalten. „Protect with Cloudflare Access“ ausgeschaltet lassen. Den Rest übernehmen.

Projektname

„iserv-zeitplaner“ ist ebenfalls möglich: Die Adresse enthält zusätzlich Ihre Cloudflare-Kontoadresse. Ist der Name in Ihrem Konto belegt, wählen Sie einen anderen. Keine vorhandene Installation überschreiben.

Einrichtungscode

Bewahren Sie den Code im Passwortmanager auf. Sie brauchen ihn anschließend auf Ihrer eigenen Website. Geben Sie ihn hier nicht ein.

Cloudflare braucht noch eine Angabe

E-Mail bestätigen: den Link im Postfach öffnen und im selben Projekt fortsetzen. workers.dev-Adresse: eine Kontoadresse anlegen. Build fehlgeschlagen: die Fehlermeldung im bestehenden Projekt prüfen. Legen Sie dafür keine zweite Kopie an.

Welche Projekte auswählen?

Ihre neu angelegte Zeitplaner-Kopie muss ausgewählt sein. Lassen Sie auch andere Projekte ausgewählt, die Sie bereits über Cloudflare betreiben. Für nicht ausgewählte Repositories funktionieren deren künftige Cloudflare-Builds nicht mehr.

Wo finde ich die Adresse?

Öffnen Sie Ihren Worker im Cloudflare-Dashboard. Kopieren Sie die feste Adresse mit der Endung workers.dev, keine Vorschauadresse und keinen Dashboard-Link.
